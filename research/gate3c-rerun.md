# Gate 3c rerun on a Nyquist grid: E2-N and E2-A

Post hoc rerun, approved by the owner on 2026-11-23, of gate 3c (rang's image of
rang's apply output against WSClean 3.7's image of the same data) for
[E2-N](e2n-native.md) (section 9.4) and [E2-A](e2-acceptance.md) (9.10, 9.13).
Branch `gate3c-rerun`. The protocol below was written and committed on 2026-11-23
before any image of this rerun existed. It was written after both legs' 3c values
had been read (they are in the notes above), so every reading here is **seen,
post hoc**. No frozen verdict is rescored by it.

Status: **E2-A dirty measured 2026-11-23: the gap remains (not setup); arm D (2026-11-24) puts it on rang's channel averaging.** E2-N running on nash.

## 1. Why

The audit in [dd2b-facet-coupling.md](dd2b-facet-coupling.md) section 4 rated
E2-N's gate 3c high risk and E2-A's medium risk. Both used 3″ pixels, coarser than
the Nyquist pixel `1/(2 max(|u|,|v|))` (about 2.35-2.5″ at 1.71 GHz). WSClean
drops the visibilities beyond the unpadded grid and rang keeps them (DD2 A3). As
frozen, neither passed `-no-min-grid-resolution`, so WSClean also gridded at its
"Minimal inversion size" (DD2 A4; E2-A's log: 3536², optimal 3584², for a 4096²
image). DD2 (amendments A2-A5) showed that with both fixed, rang's and WSClean's
dirty images agree to 4e-8 of the peak.

The recorded readings were:

| Leg | Dirty L∞ / peak, as frozen | Dirty L∞ with `-no-small-inversion` (seen) | Within 0.7° | Compact sources (inner 0.7°) |
| --- | ---: | ---: | ---: | --- |
| E2-N | 5.50e-2 | 5.50e-2 | 3.3e-3 | n 312, median 0.9964, scatter 2.68 % |
| E2-A | 5.0e-3 | 4.97e-3 | 2.7e-3 | n 248, median 0.9969, scatter 3.6 % |

Both notes attributed the gap to channel averaging: GeMClean grids 512 averaged
channels (`-average-channels` 2 on E2-N, 8 on E2-A), and WSClean 3.7, which has no
such option, grids all 1,024 or 4,096. The audit notes that this was never
separated from the grid setup.

## 2. What is rerun (changed: the pixel, the grid flag, nothing else)

- **rang's products.** Each leg's own apply output (CORRECTED_DATA, which is
  CORRECTED_1GC and the original 3c input `RANG_CORRECTED_DATA`), with FLAG after
  apply and unit weights. These are gone from both hosts (section 4), so they are
  regenerated by rerunning **only the apply stage**. It runs on a copy of the
  leg's MS with the leg's own surviving calibration tables and flag versions,
  using `rang-core apply CONFIG MS --run-dir RD --force`. That command first
  restores the flags saved before apply. Section 3 gives the checks that the
  regenerated products are the originals.
- **rang's image.** GeMClean with the image stage's own argv, taken from
  `image/summary.json` of the leg's run directory. Only `-name`, `-size` and
  `-scale` change; the dirty arm also sets `-niter 0`. The image stage is that
  same gemclean call, so the dirty image is the image stage's first dirty image.
  `-average-channels` stays as frozen (2 on E2-N, 8 on E2-A).
- **WSClean.** The same translation as the original step
  (`e2_post.wsclean_argv`: every shared argument as passed, `-gridder wgridder`,
  `-average-channels`, `-unit-weights` and `-scans` dropped as before), on
  CORRECTED_DATA in the matched state. That state is WEIGHT_SPECTRUM renamed away
  and a unit WEIGHT, as E2-B's `UNIT_PY`; FLAG is already rang's FLAG after
  apply on the copy. **`-no-min-grid-resolution` is added to every WSClean call**,
  including the controls. Containers: E2-A uses `rang-wsclean-native:3.7` (Docker
  in WSL on glacier), as frozen. E2-N uses the KERN WSClean 3.7 in
  `rang-o-casa_6.7.6.14.sif` (apptainer on nash), as E2-N's amendment 2. WSClean's
  `-temp-dir` is on local disk: WSL ext4 on glacier, the run root on nash.
- **Grid.** The pixel is 2″ and the image 6144², which keeps the frozen field
  (4096 × 3″ = 12,288″) exactly. This is valid if 2″ ≤ `1/(2 maxuvw)` at the
  highest channel, with `maxuvw` the largest `sqrt(u²+v²)` in wavelengths that
  WSClean logs (an upper bound on `max(|u|,|v|)`). E2-A's frozen log gives
  maxuvw 43,244.3 λ, so Nyquist is at least 2.385″. E2-N's value is read from
  its 3″ control's log before any Nyquist arm runs. If it gives less than 2″, the
  grid is 1.5″ and 8192² instead.
- **Logs.** Each WSClean log is checked for no "Minimal inversion size" line.
  Its gridded visibility counts are recorded beside rang's (`channels[].rows` or
  weight sums in GeMClean's report, where present).
- **Scorer.** [e2_score3c_a.py](results/e2-acceptance-scripts/e2_score3c_a.py),
  unchanged. It reads a `rang-run/` directory with `image/summary.json` and
  `config.resolved.json`; for each arm those are the leg's own, with the argv of
  the gemclean call actually run. Dirty arms are scored with `--dirty-only`.
- **Tolerances as frozen** (A0 6.1 row 3c): dirty L∞ ≤ 1e-6 of WSClean's peak per
  channel and MFS; compact sources within 0.7°, median within 0.5 % of 1 and robust
  scatter ≤ 1 %.

## 3. Arms, controls and order

Per leg:

| Arm | rang | WSClean | Scored |
| --- | --- | --- | --- |
| C3 (control) | the leg's archived 3″ image-stage FITS (E2-A: its run directory; E2-N: the follow-up's bit-identical rerun, below) | 4096² at 3″, `-niter 0`, `-no-min-grid-resolution`, on the regenerated data | dirty only |
| N (gated reading) | 6144² at 2″, gemclean `-niter 0` (dirty), then as the image stage (clean) | 6144² at 2″, dirty and cleaned | dirty L∞, then compact |
| D (diagnostic, labelled, not gated) | arm N's dirty with `-average-channels 1` | arm N's dirty | dirty only |

**Controls: the regenerated products are the originals.**
- **R1.** After the forced apply, FLAG's SHA-256 equals the leg's saved version
  `flags.rang_selfcal_*` ("flags before selfcal", that is FLAG after apply). If
  not, the leg stops and is reported.
- **R2.** The apply entry's `config_sha256` equals the original's (E2-A
  `97c43a7b…`). E2-N's is checked against the follow-up's run directory.
- **R3 (E2-A).** C3's WSClean dirty images equal E2-A's archived
  `wsclean3c-a-nosi` FITS (same binary, same data, `-no-small-inversion` being
  the old name of the flag) to ≤ 1e-6 of the peak per image.
- **R4.** C3 scored reproduces the recorded seen reading (E2-N 5.50e-2, E2-A
  4.97e-3) within 1 % relative.

If R3 or R4 fails, the leg's arm N is still run and scored, labelled "against
regenerated products that do not reproduce the original", and the cause is
recorded.

**Binaries.**
- **E2-N:** E2-N's wheel, rebuilt bit-identical by the follow-up
  ([e2n-followup](https://github.com/gijzelaerr/rang-core/blob/e2n-followup/research/e2n-followup.md),
  2026-11-22 amendment; extension `9c42ea72…83ed`). It is installed into a fresh
  venv with the follow-up venv's pins. The follow-up's rerun with this binary
  reproduced E2-N's saved flag versions (the flags before flag, calibrate and
  apply) bit for bit (`fu-flagversions.json`, `all_equal: true`). Its
  calibration tables and 3″ images are therefore used as E2-N's (copied, not
  read in place).
- **E2-A:** the frozen venv (`20261111-e2-wheel`, extension `616b1a32…`) no longer
  exists, and no surviving 0.1.0 wheel has that extension. The wheel is rebuilt
  with `maturin build --release --locked` at `b2d80dcd`, the commit carrying E2's
  section 6.4, with today's toolchain. Its extension hash is recorded. It is
  expected to differ (other rustc, other path), so R3 and R4 carry the identity.
  The Python package is byte-equal at that commit.

**Order:** copy, apply (R1, R2), matched state, C3 (R3, R4), then N dirty, then
N clean, then D. N's dirty is scored before N's clean is read.

**E2-A's clean arm (the compact row) is not run on glacier.** GeMClean's Stokes I
multiscale path held 41 GB at 4096² on E2-N's case I
([gemclean-mem-32.md](gemclean-mem-32.md)). About 21 GB of that scales with
image area, so 6144² needs about 47 GB plus E2-A's 7-8 GB of visibilities. That
is above what the 63 GB host can give one job beside Windows and WSL. The
compact row on E2-A is "not run (memory)" unless the coordinator moves it to nash
(about 7 h to upload the target rows at 5 MB/s). The dirty arms need about
10-15 GB.

## 5. Decision rule (frozen before any image of this rerun)

**The verdict is per leg and as frozen.** Dirty L∞ of arm N ≤ 1e-6 gives "met",
otherwise "not met". The compact row is met as frozen, or not met, or not run.

**Was the original gap setup, or does it remain?** Let N = arm N's dirty L∞ and
C = arm C3's (the 3″ reading with the grid flag).
- **Setup:** N ≤ 1e-4. That is the floor of `-wgridder-accuracy` 1e-4 in both
  arms, which E2-B 9.17 measured at 2.0e-6 to 2.2e-5, rounded up. The 1e-6
  tolerance cannot be met at that accuracy even when the setup is perfect, so a
  "setup" reading may still be "not met" as frozen.
- **Partly setup:** 1e-4 < N ≤ C/10.
- **Remains:** N > C/10.
- **Arm D**, read only if the class is not "setup": if D ≤ 1e-4, what remains
  is rang's channel averaging, which is a difference of configuration, not of
  imager. Otherwise it is unexplained.
- **Compact row** (E2-N, and E2-A if it is run): met as frozen is read as the
  scatter being setup. Otherwise the scatter is reported beside the original
  (2.68 %, 3.6 %) and the gap is read as remaining.

Not in scope: CASA, the target oracle row, any other gate.
