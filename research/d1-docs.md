## Tool decision: Sphinx

Sphinx 9.2 with `autodoc`/`autosummary`, `myst-nb` (MyST Markdown pages and
notebook rendering) and the `furo` theme, not MkDocs with `mkdocstrings`.
The deciding feature is the API reference from the core wrappers'
docstrings: Sphinx autodoc imports `rang` with the compiled `rang._core`
present, so what it documents is what a user imports, and a trial strict
build (`-W --keep-going`, `automodule :members:` over all 67 modules under
`python/rang/`, the 66 public ones plus `notebook._plot`, 2026-10-30)
documented 453 objects with 11 warnings and no import failure; every warning
had one cause, `|x|` read as an RST substitution, which a docstring hook in
`conf.py` escapes without touching the shared modules. The docstrings are
plain prose with backtick code spans, which `default_role = "literal"`
renders as code. `myst-nb` renders the five notebooks without pandoc (which
`nbsphinx` needs and no apt install may provide), and the pages stay in
Markdown like the rest of the repository. MkDocs with `mkdocstrings` would
have parsed the same docstrings statically (griffe) and so would not prove
the extension imports; it would also have added a second Markdown dialect
for no gain here. (This paragraph was committed first, `ad155f8`, with a
miscounted "61 modules", corrected here.)

Research pages link to `research/*.md` on GitHub (`{gh}` and `{ghdir}`
roles in `conf.py`) instead of pulling the reports into the build, so the
reports' relative links cannot break the strict build and the reports stay
the single record.

Logo: `docs/logo/render.py` renders the text-free marks with **resvg-py
0.5.0** (resvg's Rust renderer as a self-contained wheel; cairosvg was not
used because it needs the system cairo library) and writes `favicon.ico`
with **Pillow 13.0.0**: `logo-{128,256,512}.png`,
`icon-{16,32,48,64,128,180,256}.png`, `icon-mono-{16,32,48}.png`, and a
favicon of 16, 32, 48 and 64 px from `icon.svg`, all committed. The
wordmark and lockups are not rasterised, because they set text in Inter,
which is not installed here and which a renderer replaces silently; the site
uses `lockup.svg` and `lockup-on-dark.svg` as furo's light and dark sidebar
logos, so the browser picks the font as for the README.

## How CI builds and deploys

`.github/workflows/docs.yml`, on every push, pull request and manual
dispatch:

1. `build` (`ubuntu-24.04`, `timeout-minutes: 20`): checkout; Python 3.14;
   `rustup toolchain install 1.93.1` (`RUSTUP_TOOLCHAIN` exported); a cache
   of the cargo registry and `core/py/target`; a venv with maturin 1.16.0;
   `maturin develop --release --locked --extras
   docs,notebook,imaging,pointing,beam` (the extension as `wheels.yml`
   builds it, with the toolchain and maturin version of that workflow); a
   backend check; the fixture through `rang.notebook.data.download_fixture`
   into a cache keyed on its SHA256; `docs/execute_notebooks.py` with
   `RANG_FIXTURE`, `RANG_NOTEBOOK_LUNO=0` and a runner-temp
   `RANG_NOTEBOOK_CACHE` (papermill, one notebook after another, executed
   copies written to `docs/tutorials/notebooks/`, a cell error fails the
   step after every notebook has run); `docs/gen_cli.py --check`;
   `sphinx-build -W --keep-going -b html docs docs/_build/html`;
   `actions/upload-pages-artifact@v3` (the `github-pages` artifact, on every
   event, so pull requests can download the site).
2. `deploy` (only `push` to `refs/heads/main`, after `build`): permissions
   `pages: write` and `id-token: write`, environment `github-pages`,
   concurrency group `pages` without cancelling, `actions/configure-pages@v5`
   then `actions/deploy-pages@v4`.

Sphinx itself never executes a notebook (`nb_execution_mode = "off"`):
papermill does it once, before the build, on copies; the committed notebooks
stay output-free. `docs/conf.py` copies the committed notebooks into
`docs/tutorials/notebooks/` when no executed copy is there (or the source is
newer), so a local build works without the fixture. The CARACAL strategy
YAMLs are not available in CI, so the comparator sections of notebooks 02
and 05 run on the teaching strategy, as D2 designed; the LUNO sections print
their skip line.

Validation: `uv tool run --from actionlint-py actionlint
.github/workflows/docs.yml .github/workflows/wheels.yml`: no findings
(0.6 s).

## Deviations

- Notebook execution uses **papermill** (allowed by the brief) instead of
  myst-nb's own execution or nbval: one execution on copies, per-notebook
  timings, `shutdown_kernel="immediate"` against the kernel-shutdown stall
  D2 saw once, and a 600 s per-cell timeout.
- The docstring hook (`_escape_pipes` in `conf.py`) escapes `|` outside
  backtick spans in every docstring; no shared module was edited.
- The quoted constants are rendered from generated MyST snippets (a table
  for `STATUS`, block quotes for the two strings) rather than `autodata`,
  whose repr of a dict of tuples would be unreadable.
- The build job uses `rustup` on the runner instead of a third-party
  toolchain action, and `actions/cache` instead of a Rust cache action.
- The installation page states, against the README's "every kernel" wording,
  that `core_wgridder`, `core_closure` and the Rust path of `fluxstd` still
  build a standalone cdylib with `cargo` from a checkout on first use (read
  from their source).

  at `configure-pages`; the `build` job and its artifact do not depend on it.

  environment protection rules are added later, `main` must be allowed to
