Status: **proposed, frozen 2026-11-20 before any code or run.** Parent: [dl-plan.md](dl-plan.md)
stage 2, [dl0-profile.md](dl0-profile.md) sections 2-4, [v040-plan.md](v040-plan.md) (#41 last, a

## 1. Question, and what is not claimed

Can the gain solver start closer to its answer than identity, so that the self-calibration solves
take fewer iterations, and is any saving left after the classical starts for a network to win?

- **Configuration served: unaveraged solves** (`selfcal.average_time: false`, rang's default). In
  the time-averaged E2 configuration, iterations are 0.25 % of the selfcal solve and 0.02 % of
  selfcal on E2-N (dl0-profile 2.2), so no start can pay there in wall time. Robustness in that
  configuration (E2-A's Sp at the 50-iteration cap, converged fraction 0.0) is out of scope here;
  at most one reported line.
- **Not claimed:** any change of default, any learned start (a network is proposed in a later
  note only if section 5's outcome H is reached), or any gain in image quality.

## 2. Present state (read, not measured)

- Every selfcal round solves `CORRECTED_1GC` (the input column) against that round's model
  (`core_pipeline.stage_selfcal`): round 2's Sa is solved from the 1GC data, not on top of round 1's
  Sp. So round 1's solution is a genuine candidate start for round 2.
- The solver starts every gain at identity (`core/src/solve.rs`, `solve_traced`: `gain: IDENTITY,
  km1_gain: IDENTITY`). Flagged or diverged gains are reset to identity. No start is passed in from
  Python.
- The streamed solve (`cal_stream`, the selfcal default) and the one-call solve give the same
  gains, flags and iterations bit for bit (selfcal-memory G1). This screening counts iterations
  on the one-call kernel.
- Pilot iterations at `solint: inf` (selfcal-memory G1c): Sp 13, Sa 37. Solve-only wall on nash:
  Sp 329 s and Sa 409 s one-call, of which the streamed read pass is 134 s.

## 3. Arms

All arms run in the same session, on the same models and the same data:

- **A0 identity:** today's solver, unchanged.
- **A1 previous interval** (finite solint only): interval k of a term starts from interval k−1's
  final gains in the same frequency bin. Interval 0 starts at identity. A gain flagged in k−1
  starts at identity.
- **A2 previous round:** round 2's Sa starts, interval by interval (matched by time centre), from
  round 1's Sp solution. Sp has unit amplitude, so this is a phase start.
- **A3 = A2, falling back to A1** where A2 has no matching interval.
- The FFT start for K is not an arm: the default selfcal has no K term.

The start enters through a new `solve_from(problem, settings, options, trace, start)` in
`core/src/solve.rs`. `solve_traced` calls it with `start = None`, so the default path is unchanged,
and the gain-hash gate and the test suite must still pass bit for bit. The Python side gets a
`start` argument on the one-call path only; the selfcal stage is not changed. Kept on the branch
only; nothing ships from this screening.

## 4. Data and runs

- **Pilot:** the four-correlation E2 pilot (one 1 h scan, 823,500 rows × 256 channels),
  regenerated by `examples/floor3_score.py`'s `cmd_copy` from `cal2.ms` (8.1 GB, on glacier
  `D:\rang\outputs\20261103-gemclean-heldout\real\`, copied to the run root on nash). Its own copy;
  no other task's directory is read.
- **Models:** one baseline `rang-core run` of the selfcal stage at the defaults (rounds 2, Sp then
  Sa, `solint: inf`) on that copy. Each round's MODEL_DATA is kept, copied to `MODEL_R1` and
  `MODEL_R2` by the driver after each predict, so every arm solves against the same two models.
- **Solve-only runs** (`examples/selfcal_memory.py solve`'s pattern, one process per solve): for
  `solint` ∈ {inf, 120 s}: Sp against `MODEL_R1` (A0, A1), and Sa against `MODEL_R2` (A0, A1, A2,
  A3). That is 12 solves, at 2 heavy-lock slots each, `RAYON_NUM_THREADS=2`, nice 19, ionice idle.
- **Host:** nash. Its disk is shared, so wall is **reported, not decided on**.

## 5. Measures, tolerances and decision rule (frozen)

- **Same solution (gate per arm):** against A0 of the same term and solint, on the parallel-hand
  products `g_p conj(g_q)` over pairs both leave unflagged: median relative difference ≤ 1e-5 and
  99th percentile ≤ 1e-4; gain flags equal. The solver's own stop criterion is 1e-7 per gain, so
  converged starts agree well inside this. An arm that fails it is reported as "a different
  solution" and is not eligible.
- **Iterations:** per term and solint, the iterations to the global stop, and per interval at 120 s
  (median, maximum). Converged fraction is reported.
- **Ceiling (computed from A0 before any other arm is read):** seconds per iteration =
  (one-call solve wall − that solve's read and set-up wall) / iterations. The read and set-up wall
  is timed by running the same solve at `max_iterations: 1`. The most a perfect start could save
  is (iterations_A0 − 1) × seconds per iteration, stated as a share of the pilot's selfcal stage
  wall. dl0-profile warns that the pilot overstates the solve's share against an E2-size stage
  (image 74 % on E2-N), so the share is also scaled to E2-N's selfcal stage, labelled as an
  estimate.
- **Outcomes** (best eligible classical arm B against A0, per term at `solint: inf` and 120 s;
  decided on iterations):
  - **N, null:** A0 needs ≤ 5 iterations, or the ceiling is < 10 % of the pilot's selfcal stage.
    Then no start, classical or learned, is worth building. #41 closes null.
  - **C, classical suffices:** B cuts the iterations by ≥ 50 % against A0 and leaves a median
    ≤ 5. A classical start is proposed (not shipped) for the default path, and no network.
  - **H, headroom:** B leaves a median ≥ 10 iterations, and the remaining iteration time is ≥ 10 %
    of the pilot's selfcal stage. Then a network start may be proposed in a separate frozen note,
    under the dl-plan stage 2 rule (wall ≤ 0.7 × B). It is not built here.
  - Anything else (between C and H) is recorded as **partial:** the classical saving is reported,
    and no network is proposed.
- **Stop rules:** one day. If `solve_from`'s parity (start = None, bit-identical) is not reached
  within 2 h, the screening reports A0 and the ceiling only, which decides between N and a
  dated amendment.

## 7. Clarification 1 (2026-11-20, during the build, before any run)

- **Where the start goes.** The selfcal Sp and Sa solves run in `rang_core::cal::diag`, the
  diagonal solver for calmodes `p` and `ap`, not in `solve.rs`. So the start is
  `diag::solve_from(problem, settings, start)`, and `solve` and `solve_counted` pass `None`. For
  `phase` only the start's phase is used; it sets the kernel's parameters. For `diag_complex` the
  gain itself is used. A gain the data leave flagged, or a zero or non-finite start, starts at unit
  gain. The binding `cal_gain_solve` takes an optional `start`, and `cal_selfcal.solve` passes it
  through on the one-call path only: averages, the streamed path and Sd are refused.
- **Tests.** Rust: no start is `solve` bit for bit, for both kinds; a start at the solution stops
  within 3 iterations at the same gains; a wrong-length start is refused. Python
  (`tests/test_dl4a_start.py`, the four selfcal-memory terms on its awkward MS): the same two
  properties, plus the refusals. The bound is 3, not 2: the stop test needs small updates on
  successive iterations.
- **A1 as run.** All intervals solve in parallel in one call. So "interval k starts from interval
  k−1's final gains" is run as A0's converged gains shifted by one interval (interval 0 at unit
  gain). This equals a sequential chain wherever the same-solution gate holds, which section 5
  checks per arm.
